# 共做 · Co-Do
**从真正想做的事开始；需要什么能力，就形成什么协作；有用的能力和关系得以延续。**

> 一个问题，一个发起者，一个 AI 协调者；需要时组队。做完了，组织可以解散，但有用能力留下来。

这句话是**最小启动模型**，不是限制必须只有一个人、一个 AI 或一种组织形态。

**真实状态（2026-10-29）：**从 `@flyoung588` 一个人开始。三个种子项目已确定为冷启动探索方向，但**尚无确认加入的外部共做者**，尚无已成立的研究团队或资助承诺。我们不先“装作有社区”，也不为了人数编造项目。

## 三个种子项目

1. **[从任务到组织：新型人机组织与论文共同研究](projects/01-organization-and-paper.md)**：研究组织、任务、协作和能力在机器经济时代如何按需生成。论文的研究与写作过程本身，也可以成为共做项目；启动时间未定。
2. **[ARIA 资助与 Agent 互动／交易协作研究](projects/02-aria-teaming.md)**：围绕合适的 ARIA 研究征集，按真实能力缺口形成跨专业申请团队；研究 Agent 之间的可信互动、协作与交易。尚未取得资助、未形成正式申请团队。
3. **[AI 自主科研](projects/03-autonomous-science.md)**：AI 实际承担科学探索，人类科研者和外部实验能力按需进入，靠真实科学证据验证结果。与已有独立研究资产的关系需要逐项确认。

## 如何参与

不必先加入组织。可以阅读相关项目、提出反例、改写问题、贡献证据、说明愿意参与的某一部分，也可以只是提出自己想做的一件事。

- **公开讨论**：通过 [GitHub Issues](https://github.com/flyoung588/recursive-productive-capacity/issues) 留言；需要 GitHub 账号。
- **不想注册 GitHub**：直接邮件 [flyoung588@gmail.com](mailto:flyoung588@gmail.com)，注明感兴趣的项目及自己的真实问题；不会因此自动成为成员。
- **参与规则**：[参与指南](PARTICIPATE.md)；成果、身份、署名和许可都不因一个评论自动转移。

## 共做不是

不是固定公司、Agent 接单平台、纯公益志愿组织、GitHub 补丁工厂，也不是序束的当然附属部门。它是**探索人和机器怎样围绕目标自主形成、运转、结束并继承能力的新型组织实践**，并长期研究实际成本、价值、权益及自我维持。

**当下只承认真实发生的事情**：已制作不等于被采用；有人回复不等于加入；发布代码不等于共同生产；记录能力不等于能力已经跨项目复用。
