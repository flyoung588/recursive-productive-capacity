# Minimal working memory / 最小协作记录
We avoid inventing management layers before collaboration exists.

When needed, a project thread can carry four lightweight facts:
1. **Thing:** who proposed what real goal and what has actually changed.
2. **Capability:** who/what performed which verified work, with limitations and reuse permission.
3. **Collaboration:** what each independent participant knowingly agreed to, changed or declined.
4. **Outcome:** what became real, who checked it and what remains open.

This is a memory of real action, **not** four forms or approval gates. First-day state is mostly blank.

Keep unreleased scientific data, private member details, identity documents, passwords and grant-sensitive material out of public GitHub. Ask before attribution or reuse. Record errors and rejected ideas as carefully as successes when they materially improve future work.
